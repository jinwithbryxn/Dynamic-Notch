# 기능 대응표 (Dynamic Notch 포크 ↔ Notchy)

## 1. 머리말

이 문서는 Dynamic Notch 개인 포크(브랜치 `notchy-parity`)에 상용 앱 Notchy의 기능을 옮기기 위한 기준표다. 기능 하나하나를 행으로 두고, Notchy 근거, 지금 포크에 있는 기능, 결정, 요구 사항, 구현 단계를 한 줄에 모은다. 문장은 입력 자료를 다시 풀어 쓴 것이며 Notchy 사이트 문구를 옮기지 않았다.

- 작성일: 2026-11-02
- 작성 방법: 아래 입력 문서 다섯 개만 읽고 정리했다. Swift 소스를 고치거나 빌드·실행하지 않았다. 실제 앱에서 확인한 내용은 없으므로 모든 기존 기능의 구현 상태는 "기존 기능(검증 필요)"로 적는다.

### 1.2 행을 만든 방법

- 한 행은 사용자가 겪는 구체적인 동작 하나다. 홈페이지 카드 하나가 여러 동작을 묶고 있으면 행을 나누고, 여러 가이드가 같은 동작을 설명하면 한 행으로 합친다.
- 소개·호환성 가이드는 독립 행을 만들지 않고 관련 행의 근거에만 적는다. 대상은 F001·F002(제품 소개), F005(얇은 소개), F007·F012·F013(노치 없는 화면·Intel·MacBook Neo 호환성), F008(다국어 속성), F032(타이머 사용법 글), F118(Face ID 안내 글), F123–F126(Claude·Codex 하위 랜딩과 한도 리셋 안내), F088(F087 페이지의 구역), F074·F071(F023·F072와 거의 중복), F003(라이브 활동 총칭)이다.
- 같은 설정이 두 페이지에 실린 경우는 한 행으로 합친다. S06-07과 S15-01(표시 화면), S01-03과 S19-23·S19-24(포모도로 단축키·Pomodoro Only), S01-04와 S09-07(받아쓰기 단축키), S05-14와 S05-15(패널 높이)가 그렇다.
- 조건에 따라 뜨는 안내 문구 행(`notchy-settings.md` 4.5절)과 값 표시 행은 해당 기능 행의 근거에 넣고 따로 행을 만들지 않는다.
- 사용자 요청 목록(A–L)의 분류를 그대로 쓴다. 요청 목록에 없는 Notchy 기능과 설정도 행으로 넣고 5절에 따로 모았다.
- 포크에만 있는 위험·정리 작업(업데이트 덮어쓰기, 에이전트 알림 경로 중복, 인증 없는 명령 채널)도 관련 분류에 행으로 넣었다.

### 1.3 열 설명

| 열 | 뜻 |
|---|---|
| ID | `M-<분류>-<번호>`. 분류는 요청 목록의 A–L이다 |
| 기능·세부 동작 | 이 행이 다루는 동작. 쌍반점(;)으로 세부 동작을 나눈다 |
| 근거 | Notchy 근거. `F###`은 기능 가이드, `S##-##`는 설정 행, `카드 #`은 홈페이지 카드 번호다. 가이드 URL은 `https://notchy.dev` 뒤의 경로만 적는다(예: `/mac-pomodoro-timer/`). S 행의 URL은 `https://notchy.dev/help/settings/`이고 페이지 앵커는 `notchy-settings.md` 1절 표에 있다. `[H:slug]`는 `https://notchy.dev/help/slug/`, `[C:vX.Y.Z]`는 `https://notchy.dev/changelog/#vX.Y.Z`, "설정 5절"은 `notchy-settings.md`의 도움말 전용 설정 표다. 포크에만 있는 행은 포크 문서를 근거로 적는다 |
| 현재 앱 | 포크에 있는 기능의 C 번호와 짧은 설명. 없으면 "없음" |
| 결정 | 유지 / 보완 / 신규 / 보류 / 폐기 확인됨 — 구현 안 함 |
| 요구 사항 | macOS 버전, 하드웨어, 권한, 외부 서비스·계정·키, 관리자 헬퍼, 비공개 API. "구현 전 확인"은 입력 자료로 확정할 수 없는 기술 판단이다 |

| 구현 상태 | "기존 기능(검증 필요)" 또는 "미구현" |
| 검증 결과 | 아직 검증하지 않았으므로 모두 "-" |
| 미지원·보류 사유 | 보류 이유, 또는 Notchy와 다르게 일부만 지원할 예정인 이유. 해당 없으면 "-" |

### 1.4 결정의 뜻

| 결정 | 뜻 |
|---|---|
| 유지 | 포크에 이미 있고 Notchy 수준과 큰 차이가 없다. 새 구조로 옮긴 뒤 동작을 다시 확인한다 |
| 보완 | 포크에 일부가 있다. 빠진 동작을 더하거나 구조를 고친다 |
| 신규 | 포크에 없다. 새로 만든다 |
| 보류 | 구체적인 이유로 지금 만들지 않는다. 이유와 풀리는 조건을 마지막 열에 적는다 |
| 폐기 확인됨 — 구현 안 함 | Notchy 변경 기록에서 제거가 확인된 기능이다. 만들지 않는다 |

### 1.6 공통 전제

- 포크: arm64 전용, `LSMinimumSystemVersion` 14.0, ad-hoc 서명(지정 요구 조건을 번들 ID로 고정), `swiftc` 직접 빌드(SwiftPM 사용 불가), Dock 아이콘 없음. Info.plist에 마이크·연락처·미리 알림 사용 목적 문구가 없다.
- 이 Mac: macOS 26.5.2, Apple silicon, 내장 화면 노치(폭 185 pt), 외부 화면 3440×1440(노치 없음).
- Notchy: macOS 13 이상, 유니버설 빌드, 필수 권한은 손쉬운 사용 하나이고 나머지는 기능을 켤 때 요청한다. 새 기능은 꺼진 채 시작한다. 포크도 같은 기본값 정책을 따른다(M-L-020).
- 유료 Apple Developer 계정이 없으므로 iCloud, App Group, ShazamKit처럼 프로비저닝이 필요한 기능은 보류 사유로 적는다.

## 4. 사용자 요청 범위 대조

요청 목록의 항목마다 그 항목을 다루는 행을 적는다. 모든 항목에 대응 행이 있다. 비고의 뜻은 다음과 같다.

- 보류 행만 있음: 대응 행이 모두 보류라 지금 계획으로는 만들어지지 않는다.
- Notchy 근거 없음: Notchy 자료에 근거가 없어 포크 요구 사항으로 정한 부분이 있다.
- 부분 근거: 홈페이지 카드·블로그·변경 기록 한 줄처럼 근거가 얇거나 낡았다.

## 6. 제약이 큰 기능의 구현 원칙

사용자가 정한 제약을 수락 기준으로 바꾼 것이다. 해당 행은 이 기준을 모두 만족해야 검증 결과를 "통과"로 적을 수 있다. 3절의 행이 "6.n절"이라고 적은 곳은 여기를 가리킨다.

### 6.1 얼굴 인식 잠금 해제 (M-J-030, M-J-031, M-J-032)

- 기능 설명, 설정 화면, 첫 안내 모두에서 "내장 카메라나 웹캠으로 얼굴을 비교한 뒤 저장해 둔 로그인 암호를 대신 입력하는 편의 기능"이라고 쓴다. "Face ID 수준", "안전한 생체 인증", "보안 기능" 같은 표현은 쓰지 않는다.
- 웹캠은 깊이를 재지 못해 사진이나 영상으로 풀릴 수 있다는 경고를 설정을 시작하기 전에 보여 준다. 민감한 Mac에는 암호와 Touch ID를 쓰라고 권한다.
- 동작 범위는 이미 로그인한 사용자 세션의 잠금 화면뿐이다. 즉 화면 잠금, 화면 보호기, 잠자기에서 깨어난 경우다.
- 다음 화면에서는 앱이 아무것도 입력하지 않는다. 설정 화면에도 그렇다고 적는다.
  - FileVault 사전 부팅 화면: macOS 사용자 세션이 시작되기 전이라 앱이 실행되지 않는다.
  - 재시동 후 첫 로그인: macOS가 암호를 요구한다.
  - 로그아웃 상태의 로그인 창, 빠른 사용자 전환 창: 다른 세션이거나 세션이 없다.
- 수락 시험은 위 네 경우를 각각 실제로 만들어 앱이 입력을 시도하지 않는지 확인한다.
- 얼굴 등록과 로그인 암호 저장·자동 입력은 서로 다른 동의다. 암호 저장은 별도 화면에서 명시적으로 켜야 하고 기본은 꺼짐이다.
  - 그 화면은 저장 위치(이 기기 전용 키체인 항목, 동기화 안 함)와 입력 방식(손쉬운 사용 권한으로 잠금 화면 암호 칸에 입력)을 설명한다.
  - 암호 저장을 켜지 않으면 얼굴이 맞아도 아무것도 입력하지 않는다.
- 암호는 macOS로 바로 검증한 뒤에만 저장한다.
- 다음 경우에는 입력하지 않는다.
  - 잠금 화면의 암호 칸이 실제로 입력 대상일 때만 입력한다. 다른 창이나 앱에는 입력하지 않는다.
  - 연속 5회 실패하면 잠시 멈춘다(Notchy v1.0.221 근거).
  - 암호가 바뀌어 입력이 실패하면 저장된 암호를 쓰지 않고 다시 설정하라고 안내한다.
- 카메라는 잠긴 상태에서 스캔하는 동안에만 켠다. 기능을 끄면 카메라, 타이머, 잠금 감시를 모두 멈춘다.
- 얼굴 데이터와 암호는 기기 밖으로 보내지 않고 로그에 남기지 않는다. 제거(M-J-032)하면 키체인 항목을 모두 지운다.

### 6.2 잠금 화면 위젯 (M-J-022–M-J-029, M-B-017)

- 이미 로그인한 세션의 잠금 화면에서만 표시한다. 로그아웃 상태의 로그인 창과 FileVault 화면은 대상이 아니다.
- 다음 요소를 가리지 않는다: 사용자 사진, 이름, 암호 칸, Touch ID 안내, 암호 힌트, 전원 단추. 위젯이 이들과 겹치면 위치를 옮기거나 숨긴다.
- 위젯 창은 키 입력 대상이 되지 않는다. 위젯을 누른 뒤에도 바로 암호를 입력할 수 있어야 한다. 이는 Notchy v1.0.221에서 고친 문제다.
- 수락 시험: 각 경우마다 위젯이 보이는지와 잠금 해제가 평소처럼 되는지 함께 확인한다.
  - 경우: ⌃⌘Q 잠금, 화면 보호기, 잠자기 복귀, Touch ID 해제, 암호 해제, 암호를 잘못 친 뒤 재입력, 외부 화면 연결.
- 제목·본문 공개 기본값은 숨김이다(M-J-029).
- 잠금 Space에 창을 올리는 방법은 비공개 SkyLight에 의존하므로 6.15절을 따른다. 그 API를 찾지 못하면 위젯을 끄고 이유를 표시한다.

### 6.3 다른 앱의 알림·메시지 (M-J-001–M-J-006, M-J-008, M-J-011–M-J-014, M-J-021)

- 기능마다 실제로 필요한 권한을 구현 전에 확인해 행의 요구 사항에 적는다.
  - Notchy 자료 기준으로 손쉬운 사용은 배너 읽기·닫기·버튼 누르기에 필수다.
  - 전체 디스크 접근은 오래된 알림 기록과 Focus 목록을 읽을 때만 필요하다.
  - 자동화는 Messages·Music·Spotify·Notes·System Events와 대화할 때 앱별로 필요하다.
  - 포크는 이 목록을 그대로 믿지 않고, 권한을 하나씩 빼 보며 확인한다.
- 권한이 없으면 그 기능은 켤 수 없다. 화면에는 어떤 권한이 왜 필요한지와 시스템 설정의 위치를 보여 준다.
- 실행 중에 권한을 주면 다시 시작해야 반영되는 경우가 있다(전체 디스크 접근 캐시, 앱 시작 때만 등록되는 배너 관찰자). 이때는 다시 시작이 필요하다고 표시한다.
- 배너 구조는 macOS 버전마다 바뀐다(Notchy는 macOS 26·27 대응을 따로 했다).
  - 확인한 macOS 버전을 설정 화면에 적는다.
  - 확인하지 않은 버전에서는 "이 macOS 버전에서 확인되지 않음"을 표시한다.
- 직접 답장은 앱별 배너 구조와 앱 버전에 의존한다.
  - 앱마다 확인한 버전을 적는다.
  - 보내지 못하면 "보내지 못함"과 앱 열기를 보여 준다. 실패를 성공으로 표시하지 않는다.
- macOS 배너를 숨기는 "노치에만" 방식에서 노치 표시가 실패하면 macOS 배너를 그대로 둔다. 알림을 잃지 않는 쪽을 택한다.
- 알림·메시지 내용은 기기 밖으로 보내지 않는다. 저장할 때는 암호화한다(M-J-005). 답장은 사용자가 전송을 누를 때만 보낸다.

### 6.4 Camera Guard (M-J-015, M-J-016, M-J-018, M-J-019)

- 문구는 "카메라를 쓰기 시작한 앱을 알리고, 고르면 그 앱에 종료를 요청한다"로 쓴다. "카메라 접근 차단", "사전 차단", "첫 프레임 방지"라고 쓰지 않는다.
- 감지는 카메라가 이미 켜진 뒤에 일어난다. 그 사이 프레임이 앱에 전달될 수 있다는 점을 설정 설명에 적는다.
- 종료는 정상 종료 요청을 먼저 보낸다. 강제 종료는 사용자가 다시 확인한 뒤에만 하고, 저장하지 않은 작업이 사라질 수 있다고 경고한다.
- 허용 목록 앱과 시스템 프로세스는 건드리지 않는다.
- 접근 자체를 막으려면 시스템 설정 › 개인정보 보호 및 보안 › 카메라에서 앱 권한을 끄라고 안내한다.
- 카메라가 켜질 때마다 띄우던 아일랜드는 Notchy에서 제거됐으므로 만들지 않는다(M-J-017).

### 6.5 앱별 오디오 믹서와 시스템 오디오 탭 (M-B-021, M-B-026–M-B-029)

- Notchy의 조건과 포크가 쓰는 API의 지원 버전을 따로 적는다.
  - Notchy 조건: Notchy 도움말은 macOS 14.4 이상과 시스템 오디오 녹음 권한을 요구한다.
  - 포크가 쓰는 API: 이 Mac의 Command Line Tools SDK 헤더(`AudioHardwareTapping.h`)는 `AudioHardwareCreateProcessTap`·`AudioHardwareDestroyProcessTap`을 macOS 14.2부터로 표시한다.
  - 14.4는 권한 흐름이나 안정성 때문에 Notchy가 고른 기준일 수 있으나 근거가 없다.
- 행의 요구 사항에는 세 가지를 따로 기록한다. 실제 쓰는 API마다 SDK 표기 버전, 실제 Mac에서 확인한 macOS 버전, 권한 요청이 동작한 버전이다.
- 포크의 최소 버전은 14.0이다. 실행 중 버전 검사로 지원하지 않는 OS에서는 믹서 탭과 스펙트럼을 숨기고 이유를 표시한다.
- 시스템 오디오 녹음 권한 설명 문구가 Info.plist에 없다. 구현할 때 추가한다(키 이름은 구현 전 확인).
- 보라색 녹음 표시가 왜 뜨는지 설명한다. 탭은 믹서나 스펙트럼이 켜진 동안에만 만든다. 둘 다 끄면 탭과 집계 장치를 지워 표시가 사라져야 한다.
- 100%로 둔 앱은 탭하지 않는다. 기능을 끄거나 앱을 끝내면 모든 앱이 원래 음량으로 돌아간다. 비정상 종료 뒤 다음 실행에서 남은 탭·집계 장치를 정리한다.
- 소리를 녹음하거나 저장하거나 전송하지 않는다.

### 6.6 외부 디스플레이·충전 한도·팬 (M-I-027–M-I-031, M-I-014–M-I-020, M-I-003, M-I-012, M-C-018)

- 기능마다 장치 지원을 먼저 감지한다.
  - DDC: 모니터와 연결 방식마다 응답이 다르다. 모니터별로 읽기 시험을 하고 응답한 항목만 조절 막대로 보인다.
  - 충전 한도: Mac 모델과 펌웨어가 충전 제어 키를 지원하는지 확인한다.
  - 팬: 팬이 있는 Mac인지, 팬 수와 회전 범위를 읽는다.
  - XDR 추가 밝기: XDR 화면인지 확인한다.
- 지원하지 않으면 기능을 조용히 숨기지 않는다. "이 장치는 지원하지 않음"과 알려진 이유를 표시한다. 예: 모니터가 DDC에 응답하지 않음, 일부 내장 HDMI 포트, 팬 없는 Mac, 펌웨어 미지원.
- 충전 한도는 macOS의 "최적화된 배터리 충전"과 함께 켰을 때 어떻게 되는지 화면에 적는다.
- 팬은 읽은 최소~최대 범위 밖으로 설정하지 않는다. 온도가 상한에 닿으면 펌웨어 자동 제어로 돌려준다.
- 복구 경로: 다음 경우마다 정상 충전과 팬 자동 제어로 돌아가야 한다. 각각을 수락 시험에 넣는다.
  - 경우: 기능 끄기, 앱 종료, 앱 비정상 종료, 헬퍼 제거, 앱 제거.
  - 헬퍼는 앱과 연결이 끊긴 채 정해진 시간이 지나면 스스로 기본값을 복원한다.
  - 앱 없이 복원하는 명령을 문서에 적는다.
- XDR 추가 밝기와 Extra Dim은 앱을 끝내거나 기능을 끄면 원래 밝기로 돌아간다.

### 6.7 AI 클립보드 (M-E-014)

- 실행 중에 Apple Intelligence 사용 가능 여부를 확인한다. 쓸 수 없으면 기능을 끄고 이유를 상태별로 표시한다.
  - 확인 대상: 기기 지원, 사용자 설정에서 켜짐, 모델 내려받기 완료, 언어 지원.
  - 지원 OS와 프레임워크 조건은 구현 전 SDK로 확인한다.
- 로컬 모델은 사용자가 직접 설치한 로컬 서버를 쓴다. 사용자가 지정한 루프백 주소만 쓰고, 찾지 못하면 "로컬 모델 없음"을 표시한다.
- 두 경로 모두 쓸 수 없을 때 외부 API로 자동 전환하지 않는다. 외부 전송은 6.9절 규칙을 따른다.
- 기본은 꺼짐이다.

### 6.8 Ask AI 비용 (M-K-013–M-K-015)

- Ask AI는 사용자의 Anthropic API 키로 호출한다. API 사용료는 Claude 구독(Pro·Max)과 별도로 청구된다. 구독으로 API 비용이 해결되지 않는다는 점을 키 입력 화면과 탭에 적는다.
- Claude Code 구독 사용량(M-K-001)과 API 비용을 같은 숫자로 합치거나 같은 표에 섞지 않는다.
- 응답마다 사용 토큰을 보여 주고, 선택 사항으로 하루·한 달 사용 상한을 둔다.
- 이 기능들은 사용자가 키 발급과 비용에 동의할 때까지 보류다. 키는 6.10절대로 다룬다.

### 6.9 외부 AI 전송은 명시적 동작으로만 (M-E-014, M-K-013, M-K-014, M-K-015)

- 화면 영역, OCR 결과, 클립보드 내용, 선택 텍스트는 사용자가 그 요청을 위해 버튼이나 단축키를 누를 때만 외부 AI로 보낸다.
- 다음은 하지 않는다: 백그라운드 자동 전송, 미리 보내 두기, 복사할 때마다 자동 요약·분류.
- 보내기 전에 보낼 내용(이미지 미리보기나 텍스트)과 받는 곳(공급자, 모델)을 보여 준다.
- 제외 앱(M-E-016)과 민감 항목(M-E-017)으로 걸러진 내용은 보내지 않는다.
- OCR(Vision)과 번역(Apple 번역)은 기본으로 기기 안에서 처리한다. 외부 전송은 그다음 단계로만 둔다.

### 6.10 키와 토큰 (M-B-007, M-D-007, M-D-012, M-K-005, M-K-007, M-K-013, M-K-026, M-J-005, M-J-030)

- API 키, OAuth 토큰, 비밀 구독 주소, 로컬 API 토큰, 암호화 키, 로그인 암호는 이 기기 전용 키체인 항목에 둔다.
- 이 값들을 두지 않는 곳: 사용자 기본값(plist), 설정 내보내기 파일, 캐시, 분산 알림.
- 로그, 크래시 보고, 디버그 출력에는 값이 아니라 "있음/없음"만 남긴다. 오류 메시지에 요청 헤더나 주소 전체를 그대로 넣지 않는다.
- 앱이 복사한 토큰은 클립보드 기록에 남지 않게 한다(M-E-017).
- 기능을 끄거나 제거 도구(M-L-021)를 실행하면 그 기능의 키체인 항목을 지운다.

### 6.11 Claude·Codex·셸 설정 수정 (M-K-017, M-K-021, M-K-024)

- 사용자 설정 파일을 고칠 때는 다음 순서를 지킨다.
  - 원래 형식(JSON, TOML, zsh)으로 읽는다.
  - 앱이 넣는 항목만 더하고, 다른 키·순서·주석·서식은 최대한 그대로 둔다.
  - 쓰기 전에 백업하고, 한 번에 바꿔 쓴다.
  - 읽기에 실패하면 고치지 않고 이유를 표시한다.
- 앱이 넣은 항목은 알아볼 수 있게 표시하거나 명령 경로로 구별한다. 끄거나 앱을 지울 때는 그 항목만 지운다.
- 셸은 `~/.zshrc`에 표식 주석으로 감싼 블록만 넣고, 끌 때 그 블록만 지운다.
- 고치기 전에 바뀔 내용을 보여 주고 사용자가 확인한다.
- 현재 상태(BASELINE 3절):
  - `~/.codex/config.toml`의 `notify`는 지금 Codex Computer Use가 차지하고 있다. 이 포크의 스크립트는 `--previous-notify` 인자 안에 `["/Users/me/.local/bin/notch-agent-done","codex"]`로 들어 있다.
  - `notify`는 값이 하나뿐이다. 앱은 이 값을 덮어쓰거나 지우지 않는다. 연결 여부는 `notify` 값 안에 `notch-agent-done`이 들어 있는지로 판단한다.
  - 앱이 `notify`를 직접 차지해야 하면, 기존 값을 이어 부르는 방식으로만 넣는다. 끌 때는 기존 값을 원래대로 돌려놓는다.
  - Claude Stop 훅은 `/Users/me/.local/bin/notch-agent-done claude`를 가리킨다.
  - 설정 창 연결 버튼은 이 훅을 "연결됨"으로 인식해야 하고, upstream `--agent-done` 훅을 겹쳐 넣지 않아야 한다.
  - 통합(M-K-017) 전까지 연결 버튼을 누르지 않는다.
- 수락 시험은 지금의 실제 설정 파일을 복사한 사본으로 한다. 켜기와 끄기를 반복한 뒤 원본과 차이가 없어야 한다.

### 6.12 에이전트 승인 버튼 (M-K-018, M-K-019, M-K-020)

- 버튼은 지금 대기 중인 요청 하나의 식별자에 묶는다. 응답은 그 요청을 보낸 훅의 응답 통로로만 돌려보낸다.
- 다음 경우 버튼을 바로 없앤다. 그 뒤에 들어온 누름은 무시하고 "이미 처리됨"을 보인다.
  - 터미널에서 먼저 답함(1초 안), 시간 초과, 세션 종료, 같은 세션의 새 요청.
- 명령 전체와 숨은 문자를 보여 준다. 잘린 명령으로는 승인하지 않는다.
- "항상 허용"은 원래 도구의 규칙 형식으로 저장하고 한 번에 철회할 수 있다(M-K-020).
- 응답 통로는 인증된 로컬 통로(6.14절)를 쓰고 분산 알림을 쓰지 않는다.
- 앱이 꺼져 있거나 답하지 못하면 원래 터미널 승인 흐름이 그대로 동작한다. 훅이 시간을 넘기면 승인하지 않고 터미널에 묻는 쪽으로 간다.

### 6.13 화면 캡처 숨김 (M-A-047, M-G-009)

- 문구는 "일부 화면 공유·녹화에서 노치를 숨기려고 시도한다"로 쓴다. 완전한 보호를 약속하지 않는다.
- 창 공유 설정을 따르지 않는 캡처 방식이 있다. 휴대폰이나 카메라로 화면을 찍는 경우도 막을 수 없다. 이 두 가지를 설정 설명에 적는다.
- 다음 도구로 확인한 결과를 macOS 버전과 함께 행의 검증 결과에 적는다: QuickTime, ⌘⇧5 녹화, Zoom·Teams·Meet 화면 공유, OBS.
- 숨김 때문에 노치가 안 보이게 됐을 때 되돌리는 방법(메뉴 막대, 단축키)을 둔다.

### 6.14 로컬 API (M-K-026, M-K-027, M-K-029)

- 루프백 주소(127.0.0.1, 필요하면 ::1)의 TCP에만 묶는다. 다른 네트워크 인터페이스에는 열지 않는다.
- 형식은 줄바꿈으로 끝나는 JSON 한 줄이다. HTTP 서버를 만들지 않는다. HTTP 요청 줄은 형식 오류로 거절한다.
- 요청마다 `token` 필드를 확인한다. 토큰이 없거나 틀리면 아무 동작도 하지 않는다. 비교는 상수 시간으로 한다.
- 토큰은 설치마다 무작위로 만들어 키체인에 둔다. 다시 만들 수 있고 로그에 남기지 않는다.
- 기본은 꺼짐이다. 끄면 수신 소켓을 닫는다.
- 요청 크기, 동시 연결 수, 초당 요청 수에 상한을 둔다. 알 수 없는 명령은 거절한다.
- 명령은 표시·상태 조회 위주로 둔다. 파일을 읽거나 쓰는 명령, 셸 명령을 실행하는 명령은 두지 않는다.
- 단축어·딥링크(M-K-027)는 별도 스위치로 켠다. 제목·본문 길이에 상한을 둔다.
- 기존 분산 알림 명령 채널은 보낸 쪽을 확인할 수 없다(M-K-029). 받을 수 있는 명령을 줄이거나 이 통로로 옮긴다.

### 6.15 비공개 API와 관리자 헬퍼의 격리

비공개 API를 쓰는 행:

- 음악·오디오: M-B-001(MediaRemote), M-B-017(SkyLight), M-B-032·M-B-033·M-B-034(블루투스 배터리, IOPS 등).
- 화면·포인터: M-G-007(SkyLight 녹화 감지), M-G-013, M-G-014(포인터).
- 입력: M-H-020(트랙패드 압력), M-H-021(가속도계), M-H-026(Spaces).
- 시스템: M-I-003(센서), M-I-021(DisplayServices), M-I-022(CoreBrightness), M-I-027(DDC).
- 통화·잠금 화면: M-J-008·M-J-010(TelephonyUtilities), M-J-022·M-J-023(SkyLight).
- 기타: M-A-044(기울기 센서).

관리자 권한을 쓰는 행: M-I-014–M-I-020(충전·팬 헬퍼), M-I-012, M-C-018(전원 설정), M-I-008(키체인 조회 승인), M-L-004(root 소유 앱).

- 비공개 API 호출은 기능별 어댑터 한 곳에 모은다.
  - 심볼은 실행 중에 찾는다. 없으면 크래시하지 않고 그 기능만 "이 macOS에서 지원 안 됨"으로 끈다.
  - 어느 기능이 어느 비공개 API를 쓰는지 설정 화면과 문서에 적는다.
  - macOS 업데이트 뒤 첫 실행에서 자가 점검을 한다.
- 관리자 헬퍼는 충전·팬을 하나로 묶는다. 기능을 처음 켤 때 설명과 함께 관리자 암호를 받아 설치한다.
- 다음 정보를 문서에 적는다: 설치 위치, 이름, 서비스 레이블, 받는 명령 목록.
- 헬퍼는 정해진 명령(충전 한도 값, 팬 모드·속도, 기본값 복원)만 받는다. 임의 명령을 실행하지 않는다.
- 호출한 쪽이 이 앱인지 확인한다. 포크는 ad-hoc 서명이라 서명 기반 확인이 약하므로 확인 방법은 구현 전에 정한다.
- 설치·제거·복구를 각각 둔다.
  - 앱 안의 제거 단추와 제거 도구(M-L-021)가 있다.
  - 앱 없이 헬퍼를 지우고 기본값을 복원하는 명령을 문서에 적는다.
  - 헬퍼와 앱의 버전이 다르면 다시 설치하라고 안내한다.

### 6.16 꺼진 기능의 자원 정리

- 기능 스위치를 끄면 그 기능의 다음 자원을 바로 멈추고 놓는다: 타이머, 파일·폴더 감시, 이벤트 탭, 오디오 탭, 마이크, 카메라, 블루투스 검색, 네트워크 요청, 하위 프로세스.
- 권한을 기다리는 재시도 타이머도 기능이 켜졌을 때만 돈다.
- 새 기능은 시작·정지를 짝으로 갖고, 정지 시험을 함께 둔다.
- 수락 시험: 기능을 끈 뒤 1분 동안 CPU, 스레드 수, 열린 파일, 네트워크 연결을 잰다. 모두 BASELINE의 유휴 측정 범위(CPU 0.0–0.2 %, 스레드 5–6)로 돌아와야 한다.
- 현재 앱에서 이 기준을 어기는 곳(앱 기능 목록 6.2절). 괄호 안의 행을 다시 검증할 때 함께 고친다.
  - 녹화 감지 1.5초 폴링: 녹화 기능을 꺼도 돈다(M-G-007).
  - HUD 이벤트 탭: HUD를 모두 꺼도 남는다. 손쉬운 사용 권한이 없으면 3초 재시도 타이머도 돈다(M-I-026).
  - 블루투스 권한 대기 3초 타이머가 돈다(M-B-031, M-B-035).
  - 전체 디스크 접근이 없으면 집중 모드를 5초마다 폴링한다(M-C-011).
  - 스크린샷 파일 감시: 스크린샷 기능을 꺼도 돈다. NSMetadataQuery 관찰자도 지우지 않는다(M-F-007).
  - 클립보드 0.5초 폴링이 돈다. 클립보드 기록(M-E-001)을 만들 때 감시기 하나로 합친다(M-F-007, M-E-001).
  - 메모리 지킴이(300초)와 업데이터(1시간) 타이머가 돈다(M-L-023, M-L-016).

### 6.17 되돌리기 어려운 시스템 변경 (M-A-030, M-B-009, M-G-015, M-G-017, M-I-012, M-I-014, M-C-018, M-L-004)

- 시스템 상태를 바꾸기 전에 원래 값을 저장한다.
  - 대상: 배경화면, 브라우저 자동화 설정, 전원 설정, 충전 상태.
  - 기능을 끄면 원래 값으로 돌린다.
  - 비정상 종료 뒤에는 다음 실행에서 돌린다.
- 키보드 청소 잠금은 다음 세 경로로 반드시 풀려야 한다. 이벤트 탭 시간 제한과 감시 프로세스로 보장한다.
  - 비상 해제 단축키, 60초 자동 해제, 앱이 멈춘 경우.
- 파일 삭제는 휴지통으로만 한다. 영구 삭제를 하지 않는다.
  - 대상: 앱 제거, 잔여 파일, 선반, 메모.
  - 현재 메모 삭제는 휴지통을 거치지 않는다. 삭제 취소(M-D-014)를 만들 때 고친다.
- 브라우저의 "Apple 이벤트의 JavaScript 허용"은 그 브라우저를 제어할 수 있는 앱이 페이지 스크립트를 실행할 수 있게 만든다. 기본은 꺼짐이고, 켤 때 이 위험을 설명한다.

## 7. 단계 계획

단계는 P1부터 P5까지 차례로 진행한다. 각 단계 안의 번호는 작업 순서다. "→"는 왼쪽 행이 끝나야 오른쪽 행을 시작한다는 뜻이다. 폐기 확인됨 5행(M-D-006, M-D-013, M-J-017, M-K-031, M-L-028)은 어느 단계에도 넣지 않는다.

모든 단계에 공통인 종료 조건은 다음과 같다.

- 그 단계 행의 검증 결과 열을 실제 Mac 확인 결과로 채운다.
- 한국어·영어 화면을 모두 확인한다(M-A-048).
- 6.16절의 자원 정리 시험을 통과한다. 기능을 모두 끈 유휴 상태가 BASELINE의 측정 범위 안에 있어야 한다.
- 로컬 커스텀 변경이 그대로 동작한다: 완료 알림 미루기, 스크린샷 감지, 녹화 오인 수정, 호버 테두리.
- 검토용 앱(`scripts/review.sh`)으로만 확인한다. 설치본 교체는 사용자가 따로 정한다.

### 7.0 시작 전 조건

- 설치본을 지키는 일을 P1보다 먼저 한다.
  - 업데이터는 꺼 둔 채로 둔다. upstream `build.sh --install`·`--run`은 쓰지 않는다(BASELINE 6절).
  - 업데이트 덮어쓰기를 막는 배포 방식(M-L-017)은 P2의 첫 작업이지만, 그 전까지 이 운영 규칙으로 대신한다.
- 에이전트 알림 경로를 통합하기(M-K-017) 전까지 설정 창의 Claude·Codex 연결 버튼을 누르지 않는다.
- BASELINE의 유휴 측정을 기준값으로 쓴다.

### 7.1 P1 공통 노치 상태 관리

목표는 여러 활동을 동시에 다루는 공통 상태, 크기를 바꿀 수 있는 패널, 탭 구조를 만드는 것이다. 이후 모든 단계가 이 위에 올라간다.

1. 상태 기반: M-L-024 → M-A-009 → M-A-007
   - 설정 창과 본 앱의 즉시 동기화를 먼저 한다.
   - 그다음 활동 공통 모델(우선순위·만료·진행률)과 일시 알림 대기열을 만든다.
   - 닫힌 열거형(`ActivityKind`, `HomeOption`, `ExpandedPage`)은 이 단계에서 등록 방식으로 바꾼다.
2. 여러 활동 표시: M-A-008, M-A-010, M-A-004, M-A-001, M-A-028, M-C-013
3. 열림과 미리보기: M-A-005, M-A-006, M-A-017, M-A-036
4. 크기·위치·화면: M-A-023, M-A-024, M-A-002, M-A-003, M-A-025, M-A-026, M-A-027, M-A-029, M-A-047
   - 720×300 pt 고정 패널을 이 단계에서 없앤다.
5. 열기·닫기 동작: M-A-011, M-A-012, M-A-013, M-A-014, M-A-016, M-A-018
6. 탭 구조: M-A-019 → M-A-020, M-A-015, M-A-022, M-A-021, M-A-031, M-A-032, M-A-046
7. 입력 공통: M-H-004 → M-H-005 → M-H-006, M-H-017
