## 4. 실기에서 찾아 고친 문제

### 4.1 종료 요청이 도우미에 먼저 감 (`4672cdb`)

- 증상: 검토용 앱이 종료 요청을 받고도 꺼지지 않아 설치 앱과 함께 떠 있었다.
- 원인: 설정·권한(첫 안내) 창은 같은 실행 파일을 같은 번들 ID의 도우미 프로세스로 띄운다. `tell application id … to quit`이 본 앱이 아니라 도우미에 먼저 가서 도우미만 끝났다. 도우미가 없을 때는 바로 꺼졌다(3회 반복으로 확인). upstream 구조에서 온 동작이며 이번 기능 추가로 생긴 것은 아니다.
- 영향: 설정 창을 연 채로 설치·복원하면 `install-local.sh`가 "did not quit"으로 멈췄을 것이다(교체는 하지 않으므로 안전하지만 설치가 안 됨).
- 수정: `scripts/install-local.sh`와 `scripts/review.sh`가 본 앱과 도우미가 모두 끝날 때까지 2초마다 다시 종료를 요청한다(최대 15초).
- 참고: 검토용 앱과 설치 앱은 명령 채널 이름(`com.dynamicnotch.app.command`)이 같다. 둘을 동시에 띄우면 한쪽에 보낸 명령을 다른 쪽도 받는다. 검토용 앱을 띄울 때는 설치 앱을 끄므로 평소에는 겹치지 않는다.

### 4.2 설정 변경 알림이 끝없이 되풀이됨 (`893e925`)

- 증상: 설치 앱에서 카메라·마이크 표시 기능(`privacy`)을 켜자 CPU를 45% 안팎으로 계속 썼다.
- 원인: 기능이 "설정이 바뀜" 알림을 받으면 `settingsChanged()`에서 같은 값을 다시 저장했고, 저장할 때마다 같은 알림이 다시 나갔다. 자체 검사는 앱을 띄우지 않으므로 이 되풀이를 잡지 못했다.
- 수정: 기능별 설정 저장(`ModuleDefaults.set`)이 값이 그대로면 쓰지도 알리지도 않는다. 한 기능만이 아니라 같은 방식으로 저장하는 모든 기능에 적용된다.
- 확인: 검토용 앱에서 기능 76개를 모두 켜고 하나씩 설정 변경 알림을 보냈을 때 CPU 1–3%. 수정본을 설치한 뒤 1차 시험 기능 5개를 켠 상태에서 CPU 0–2%, 메모리 약 73MB.

### 4.3 시스템 설정에 앱이 두 개로 보임 (`89d9c33`)

- 증상: 사용자가 시스템 설정에서 Dynamic Notch가 두 개 보인다고 알렸다.
- 원인: 검토용 앱도 로그인 항목에 스스로 등록했고, 한국어 표시 이름 파일 때문에 이름이 설치 앱과 같은 "Dynamic Notch"로 보였다. 빌드 폴더에 남은 예전 시험 빌드 10여 개도 LaunchServices에 같은 번들 ID로 등록돼 있었다.
- 수정
  - `scripts/review.sh`: 검토용 앱의 표시 이름을 모든 언어에서 "Dynamic Notch Review"로 바꾸고, 첫 안내(권한 요청) 창을 띄우지 않게 한다.
  - 개발용 실행 인자 `--login-item=off`: 로그인 항목 등록을 지운다. 검토용 앱의 등록을 이것으로 지웠다.
  - `scripts/install-local.sh`: 설치 뒤 빌드 폴더 사본의 LaunchServices 등록을 지운다. 빌드 폴더에는 `.metadata_never_index`를 두어 Spotlight가 사본을 다시 등록하지 않게 했다.
  - 남은 시험 빌드의 등록을 지웠다(파일은 지우지 않음).
- 확인: LaunchServices에 남은 등록은 설치 앱(`/Applications`)과 이름이 다른 검토용 앱 두 개다. 개인정보 보호 목록에 "Dynamic Notch Review"가 보이면 검토용 사본이며, 그대로 두거나 사용자가 "-"로 뺄 수 있다.

### 7.1 내가 잰 것

| 시점 | 켜진 기능 | CPU (`top` 1초 간격) | 메모리 |
|---|---|---|---|
| 1차, 4.2절 수정본 설치 뒤 | 기본 10개 + 1차 5개 | 0–2% | 약 73MB (RSS) |
| 3차, 창 지켜보기를 멈춘 뒤 | 기본 10개 + 1–3차 기능 | 0.4–0.9% | 약 85MB (RSS) |
| 4차 뒤 | 기본 10개 + 직접 켠 17개 | 1.7–2.5% | 약 92.5MB (RSS) |

- 네 차례 내내 CPU는 0.4–2.6% 안에 있었다. 메모리 지킴이 기준(150MB + 기능당 3MB)보다 낮다.
- 시험 뒤에도 켜 둔 기능: `calendar`, `reminders`, `weather`, `privacy`, `btbattery`, `windowsnap`, `textactions`, `snippets`, `cleaning`, `menubar`, `capture`, `windowwatch`, `dictation`, `spectrum`, `soundmixer`. 선택 텍스트 막대와 메뉴 막대 화살표는 켜 두면 계속 보인다.
- `typingsounds`와 `presenter`(키 입력 표시·클릭 물결)는 사용자 요청으로 시험 뒤 껐다. 끈 뒤 앱의 키 누름 이벤트 탭이 사라지고(`CGGetEventTapList`로 확인, 남은 하나는 기존 볼륨·밝기 표시용 `HUDMonitor`), CPU 0.2%였다.

### 7.2 이번 시험으로 확인하지 못한 것

- 시험한 기능 안에서도 해 보지 않은 세부 동작은 `FEATURE-MATRIX.md` 상태 칸에 "실기 미검증"으로 남겼다. 예: 미리 알림 추가·완료, 주간 일정·회의 참가, 현재 위치 날씨, 반복 키 스냅의 다음 화면, 선택 텍스트 막대의 버튼별 동작, 포인터 후광·스포트라이트, 받아쓰기 단축키 시작, 앱별 볼륨 150%·음소거·값 기억, AirPods 좌우·케이스 값, 블루투스 배터리 부족 경고.
- 마이크 사용 표시(M-J-016), Camera Guard(M-J-018, M-J-019), EQ·출력 장치(M-B-027–M-B-029), 실제 화면 녹화 표시·정지(M-G-007)는 이번에 시험하지 않았다.
